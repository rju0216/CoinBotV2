## 0. 문서 목적

PATH_C 에서 **기존 전략(15m ensemble ML 단기 방향예측)의 edge 가 lookahead 의존이었음**이 확정됐다. causal 환경에서 진짜 edge 를 낼 새 전략을 찾되, ML 방향을 포기하지 않는다. 단 "비싼 재학습"을 바로 하지 않고, **무엇을(어떤 타깃을) 맞힐 수 있는지 먼저 싸게 측정(Phase R)** 한 뒤, 측정 결과가 정당화하는 방향으로만 학습/구현한다. 본 PATH 는 그 측정(Phase R) → 분기(ML 재학습 or 룰베이스) 를 한 흐름으로 관리한다.

## 1. 배경 (PATH_C 계승)

### 1.1 확정된 사실
- **15m 단기 방향 3-class 분류 ML 은 causal 환경에서 edge 없음** (PATH_C §7): walkforward 33 folds (lightgbm 857건 PF 0.83 / xgboost 1583건 PF 0.79), 승률 ~30% < 손익분기 ~33%, 누적 -$9.8k/-$22.7k. ensemble/DL 은 진입 0건.
- 과거 모든 백테 성과(OOS 1118%, 백테 79% 승률 등)는 lookahead 부풀림.
- 라이브 v010 수익(+$594)은 운으로 확정 (P-C-3.6: 과거 재현 시 -20.39%).

### 1.2 실패의 근본 원인 (단기 방향 예측의 한계)
1. **타깃 설계 불리**: 15m 다음 방향은 SNR 극저 — 예측 가능 성분이 거의 없음. ML 이 잡은 "edge" 정체가 lookahead(상위TF 미래 완성봉)였음.
2. **승률 의존 보상구조**: TP:SL 2:1 고정 → 손익분기 ~33%. causal 승률 ~30% + 비용 → 구조적 음의 기대값.
3. **거래비용 대비 edge 과소**: 15m 빈도 왕복 수수료 ~0.1% + 슬리피지가 미세 우위를 잠식.

### 1.3 핵심 전환 방향
- **병목은 input 표현이 아니라 타깃**: 기존 DL(LSTM/Transformer)이 이미 lookback 60봉(=한 TF 여러 봉) × 15m/1h/4h causal merge(=여러 TF 종류) × 81 feature 를 학습했고 causal 에서 0건/edge 없음. input 을 더 키우는 건 한계효용 낮음.
- **한 번도 안 바꾼 축 = 타깃·horizon**: 모든 모델이 "15m 다음 방향 3-class" 하나만 학습. 더 긴 horizon·R-multiple·변동성·레짐 라벨은 미시도.

## 3. Phase R 설계 (예측력 측정)

### 3.1 2단계 체 구조 (싼 체 → 정밀 체)
- **R-1 — 단일 feature IC 스캔 (학습 0, 초고속)**: 각 (feature, 타깃) 조합의 순위상관(IC)만 계산. "어떤 타깃이 어떤 feature 와도 상관 없다"를 1차 거름.
- **R-2 — 가벼운 다변량 모델 예측력 + 비용차감 기대값**: R-1 통과 타깃에 대해 얕은 모델(선형/depth-제한 lightgbm)을 OOS fit → 4자(IC/AUC/분위수 단조성/비용차감 기대값) 산출. feature 상호작용 + input축(TF×봉수) 효과 측정.

### 3.2 측정 매트릭스 (초기 범위)
- **input 축**: TF {15m, 1h, 4h, 1d} × 봉수(현재값/단기요약/장기요약) × feature 27종(`BASE_FEATURE_NAMES`)
- **타깃 축**: horizon {1h, 4h, 1d} × 라벨 {방향, R-multiple, 변동성, 레짐}

라벨 정의(미래값은 *정답 라벨*에만 — input 누출 금지):
- 방향: `sign(close[t+H] − close[t])`, dead-zone 적용 3-class
- R-multiple: ATR 정규화. t 진입 후 H 동안 `MFE/ATR` vs `MAE/ATR`
- 변동성: `[t, t+H]` realized volatility (회귀)
- 레짐: efficiency_ratio/ADX 기반 추세 vs 횡보 (또는 미래 경로효율)

### 3.3 OOS 재현 = 연도별 walkforward
- 2020·21·22·23·24·25·26(부분) 구간별로 같은 칸이 재현되는지 확인.
- R-1: 각 연도 구간에서 IC 독립 계산 → "N구간 중 몇 곳에서 |IC| 문턱 넘나"로 재현성 판정.
- R-2: walkforward(직전까지 train → 해당 연도 OOS).

### 3.4 causal·snooping 방어
- input feature: t 시점까지만 (P-C-1 causal merge). 라벨만 t+H 미래 사용.
- "전체계산 == 윈도우계산" 불변 점검을 측정 코드에도 적용.
- 다수 연도 구간 재현 필수. 단일 구간 강세 기각(다중검정 함정 방어).

### 3.5 산출물
- 1회용 측정 스크립트(탐사용 → commit 제외, 규칙 8-4) + 결과 매트릭스 표(히트맵)를 본 보고서에 보존.
- C6 분기 결정 근거.

### 3.6 R-1 운용 규칙 (확정, 2026-06-23)
- **합격 판정 (칸 단위)**: 칸 = (feature × TF × horizon × label). `|IC| ≥ 0.03` & `≥ 5/7년 부호일관`.
- **거르기 단위 = 타깃(horizon × label). OR 통과**: 어떤 타깃에 대해 27 feature × 4 TF 중 *단 하나라도* 칸이 합격하면 그 타깃은 **생존 → R-2**. 모든 feature·모든 TF에서 다 실패할 때만 타깃 **폐기**. (관대한 통과 → false negative 최소화)
- **R-multiple 라벨**: `fwd_return/ATR` 단순형. (MFE-MAE 경로기반은 R-2 비용차감 기대값 시뮬에서 정밀화)
- **측정 범위**: same-TF 만 (각 TF feature ↔ 같은 TF 타임라인의 절대시간 horizon). cross-TF 융합·봉수(lookback) 효과는 R-2 다변량에서.
- **R-1의 본질적 한계 (감수)**: 순수 다변량/cross-TF 상호작용으로만 존재하고 어떤 단일 feature 로도 IC=0 인 신호는 R-1 이 놓칠 수 있음. OR 통과 + 보수적 임계(0.03)로 완화. 잔여 위험은 감수.

### 3.7 R-1 vs R-2 역할 분담
| 보는 것 | R-1 (단일 IC) | R-2 (가벼운 다변량) |
|---|---|---|
| 신호 존재 여부 | ✅ 1차 거르기 | ✅ 정밀 |
| 방향성 라벨 | ✅ fwd_return/ATR | ✅ |
| MFE-MAE R-multiple | — | ✅ 비용차감 기대값 시뮬 |
| cross-TF 융합 | — | ✅ 다변량 |
| 봉수(lookback) 효과 | — | ✅ |
| AUC·분위수 단조성·비용차감 기대값 | — | ✅ 4자 전부 |

### 4.1 R-1 구현 사양 (확정)
- **스크립트**: `scripts/_tmp_r1_ic_scan.py` (1회용, commit 제외). 재사용: `compute_features`, `HistoricalDataLoader.load_from_csv`, `compute_atr`.

- **horizon(절대시간) → TF별 봉수 환산**: 15m {1h=4, 4h=16, 1d=96} / 1h {1h=1, 4h=4, 1d=24} / 4h {4h=1, 1d=6} / 1d {1d=1}. TF 봉보다 짧은 horizon 은 생략 → (TF,horizon) 9조합.
- **라벨(causal, `shift(-H)`)**: 방향 `fwd_return=close[t+H]/close[t]-1` / R-multiple `(close[t+H]-close[t])/ATR[t]` / 변동성 `[t+1,t+H] realized vol` / 레짐 `|close[t+H]-close[t]|/Σ|Δclose|`.

- **칸 규모**: 27 feature × 9 (TF,horizon) × 4 label × 7 year ≈ 6,800 IC. CPU 수십 초.
- **causal 점검**: feature 미래누출 0(전체=윈도우 불변) + 라벨만 미래 shift 확인.

### 4.3 R-2 설계·사양 (확정, 2026-06-23)
**방식**: 계층적 ablation — 코어(①레짐필터 + ④조건부분리) go/no-go → 양수 시 ②사이징·③동적SL/TP 증분.
**결정**: 모델=선형(릿지 회귀), 레짐=변동성 분위수 3구간, 비용=보수적 taker.

**코어 사양 (①④)**:
- **entry_tf**: 1h (R-1 평균회귀 생존 구간). **feature**: 평균회귀 기여(body_ratio·return_1·return_5·rsi_7·rsi_14·price_ema10_ratio·bb_position) + 변동성(atr_pct·volatility_20·bb_width).
- **모델/라벨**: 릿지 회귀로 `fwd_return_1h = close[t+1]/close[t]−1` 예측 → 예측 부호·임계로 진입(평균회귀는 음의 계수로 자연 표현).
- **레짐**: 1h `atr_pct` 분위수 3구간(저/중/고). ⚠️ **경계는 train 구간에서 산출 후 OOS 적용**(누출 방지). 레짐별 조건부 예측·시뮬 분리 → "저변동=평균회귀 / 고변동=추세" 검증.
- **비용차감 시뮬**: 진입=다음 1h 봉 시가(보수적). 청산=±1 ATR SL/TP(RR 1:1) + 최대 4봉 타임청산, MFE-MAE 먼저 닿기. 비용=taker 0.05%×2 + 슬리피지 1bp×2 + funding(~0). `FeeModel` 파라미터 차용.
- **walkforward**: 연도별 expanding(2020 train→2021 OOS … ), OOS 2021~2026 (6년).
- **go/no-go 합격선**: 레짐 중 ≥1개에서 거래당 net PnL>0 & PF>1 & 양수 OOS ≥4/6년.

**ablation (코어 양수 시)**: 코어 baseline → +②변동성 타깃 사이징 → +③동적 SL/TP. 각 baseline 대비 증분 순효과만 측정.

**측정 단계**: `scripts/_tmp_r2_meanrev_sim.py`(1회용, commit 제외) 가벼운 자체 시뮬로 go/no-go. edge 확인 시 → C6 분기에서 정식 plugin + BacktestEngine(라이브-백테 일관) 재검증.

- **릿지 mean_coef ±0.00003 극소** — 사실상 방향 신호 없음. high 만 약한 음수(평균회귀), low/mid 약한 양수. 어느 쪽이든 비용 못 넘음.

**R-2 결론**: 1h 평균회귀는 **비용차감 후 명확한 손실**. 변동성 레짐 분리(①④)로도 구제 안 됨 — 어느 레짐도 양수 fold 0. 코어가 전 fold 음수라 ②사이징·③동적SL/TP **증분 생략**(없는 edge 다듬기 무의미). → **단기 방향 ML(평균회귀 포함) 최종 가망 없음 확정.** C6 분기 = **룰베이스 전환**.
