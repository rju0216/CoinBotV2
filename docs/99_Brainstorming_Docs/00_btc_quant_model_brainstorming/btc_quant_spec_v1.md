# BTC 무기한 선물 퀀트 시스템 — 1세대 설계 스펙

> 본 문서는 설계 세션에서 분석·논의·합의한 내용을 정리한 1세대(v1) 구현 스펙이다.
> "발견(자유) → 매핑(번역) → 매매(규칙)" 3층 구조를 따른다.
> 모든 계수는 매직넘버로 박지 않고 **백테스트 스윕으로 정당화**하는 것을 원칙으로 한다.
>
> **[문서 성격]** 본 문서는 v1 *설계 원안(스냅샷)*이다. 구현 과정의 결정·이탈·현재 상태(예:
> 일부 설계의 gen1 채택 여부)는 작업보고서 `docs/00_Work_Reports/01_btc_quant_model_v1_design.md`
> 를 정본으로 한다. gen1 최종 구현체 스펙은 gen1 완료(D4-5) 후 별도 as-built 문서로 작성 예정.

---

## 0. 설계 철학

- **레짐 판단은 데이터가 자유롭게**, **매매는 확실한 규칙으로 조인다.**
- 두 층 사이에 **고정된 인터페이스(contract)**를 둔다. 안쪽 모델(HMM 등)을 갈아끼워도 매매 로직은 불변.
- 핵심 원칙: **표본이 적은 곳일수록 모델에 자유를 덜 줘야 일반화된다.**
  - 레짐 발견 = 전체 데이터 사용 → 표본 많음 → 자유 OK (비지도)
  - 매매 행동 = 특정 구간만 사용 → 표본 적음 → 자유 위험 → 규칙으로 조임
  - (이 이유로 "레짐별 RL 에이전트가 행동까지 학습" 안은 1세대에서 제외. 데이터 부족 시 RL은 자유로운 학습이 아니라 과거 외우기(과적합)로 귀결됨.)

## 1. 발견 레이어 (Discovery) — 비지도 레짐 판단

### 1.1 종목 / 봉 주기 / 데이터 구간
- **종목**: BTC 무기한 선물 단일 종목
- **봉 주기**: 1h
  - 선택 이유: fat tail은 어차피 해결할 문제로 규정 → 1h를 피할 이유(fat tail 회피)가 사라짐 → 남은 기준은 매매 빈도 선호 → 1h.
- **학습 구간**: 2020-01-01 ~ 현재
  - 2022년 약세장(69K→15.5K, 약 1년)이 통째로 포함되어 **trend/short 표본 확보**.
  - 시장 구조(기관화·ETF·성숙한 무기한 시장)가 라이브와 정합적.
  - **2017~2018은 학습에서 제외**: 무기한 시장 미성숙·유동성 구조 상이 → 분포 오염 위험. 단 **스트레스 테스트용으로 별도 보관**(극단 약세장 반응 점검).

### 1.2 입력 feature (코어 3개)
모두 정상성(stationarity)을 갖는 형태여야 하며, 가격 절대수준은 넣지 않는다(가격대를 레짐으로 오인 방지).

| feature | 정의 | 윈도우 | 담는 정보 |
|---|---|---|---|
| 로그수익률 | `log(P_t / P_{t-1})` | 1봉 | 방향(부호) + 모멘텀(크기) → direction |
| 변동성 | 실현변동성 또는 정규화 ATR | **24봉(1일)** | 저변동/고변동 구분, 반응성 |
| 효율성비율(ER) | Kaufman ER = 순변화 ÷ 경로합 | **48봉(2일)** | 추세성(0=횡보, 1=추세) → type |

- **표준화**: 전 feature z-score. 표준화 파라미터(평균·표준편차)는 **train 구간에서만** 계산하여 test에 적용(미래 누수 방지).
- **차원 절제**: 1세대는 3~5개로 시작. 거래량·펀딩비·OI 등 미시구조 정보는 레짐이 아니라 **트리거 단계**에서 사용(정보 위생).
- 데이터 앞부분 48봉은 feature NaN으로 학습에서 제외(무시 가능한 손실).

### 1.3 윈도우 정책 (보유기간 1~3일 기준 역산)
- ER/추세성 윈도우 = 매매 호흡과 같게 → **48봉(2일)** 기본.
- 변동성 윈도우 = 더 짧게(반응성) → **24봉(1일)**.
- ATR(contract volatility 필드용) = **24봉** (← 14봉은 차트툴 legacy일 뿐 근거 없음. 레짐 변동성 스케일과 일치시키기 위해 24봉으로 정정).
- 최소 윈도우 하한 = **24봉**(통계적 하한 ~20봉 + 여유).
- 멀티스케일 feature(24·48·72봉 동시)는 2세대 백로그.

### 1.4 모델
- **Student's t emission HMM** (fat tail 정면돌파).
  - 가우시안 emission은 크립토 fat tail에서 ① 극단 사건을 "불가능"으로 취급해 상태 추론 왜곡 ② 분산 추정 오염 ③ 가장 중요한 패닉/급락 레짐에서 가장 부정확.
  - t-분포는 자유도 ν로 꼬리 두께 조절(데이터가 추정, 상태별로 다른 ν 허용 가능).
  - 비용: `hmmlearn` 기본 미지원 → 직접 구현 또는 `pomegranate` 등 사용. 구현 난이도 한 단계 상승(인지하고 진행).
- fat tail은 짧은 봉일수록 심함(시간분해 효과: 긴 봉일수록 정규분포에 수렴). 1h는 fat tail이 두드러져 t-분포가 더 필요.

### 1.5 K(상태 개수) 선택 — 세 렌즈 종합
데이터가 정하되, 후보 범위 K=2~6에서 세 기준을 겹쳐 본다.

1. **Holdout log-likelihood**: train으로 추정한 모델이 validation을 얼마나 잘 설명하나. 과적합 방지. elbow에서 선택.
2. **BIC**: 우도 + 파라미터 수 페널티. 불필요한 복잡도 방지. (t-HMM은 ν까지 파라미터라 BIC 특히 중요.)
3. **커버리지**: 각 K에서 매핑을 돌려 **trend/long · trend/short · range/none 세 조합이 채워지는지** 확인. 통계적으론 좋아도 매매상 쓸모없는 K를 거름.

- (1)(2)는 "모델이 데이터에 맞나", (3)은 "모델이 내 목적에 맞나". 둘 다 통과해야 함.
- 실무적 sweet spot은 K=3~5 예상이나, 최종은 데이터가 결정.

### 1.6 추정 절차 (정직성의 핵심)
- **파라미터 추정(EM/Baum-Welch)**: train 구간 전체.
- **상태 추론**: 반드시 **filtering (forward-only)**. smoothing/Viterbi 금지(미래 누수 → 백테스트만 좋고 라이브 붕괴).
- **walk-forward 재추정**: 주기적으로 train 윈도우를 굴려 재추정(레짐 통계 drift 대응).

### 1.7 K개 상태 → 라벨? (오해 방지)
- K 설정은 "추세상승/하락/횡보를 만들어라"가 **아니라** "데이터를 K개 덩어리로 묶어라"일 뿐.
- 모델은 임의 번호의 상태와 그 통계(평균수익률·분산·전이확률)만 출력. 라벨은 안 붙음.
- "추세상승" 같은 이름은 **매핑 규칙을 통과한 결과**지 사전 지정이 아님.
- **K를 키워도 빠진 조합이 보장되지 않음.** 데이터에 없는 레짐은 발견되지 않음(K는 해상도만 정함, 커버리지는 보장 못 함).
  - 경우 A(해상도 부족): K 키우면 빠진 조합 등장 → 해결됨.
  - 경우 B(데이터 빈약): K 끝까지 키워도 안 나옴 → 학습구간 확장 / 해당 레짐 관망 / (비권장)대칭가정.
  - 빈 조합은 **억지로 채우지 말고 정직하게 비워둔다**(미발견 레짐 = 관망).

## 2. 매핑 레이어 (Mapping) — 상태 → contract 자동 번역

### 2.1 Contract (고정 인터페이스, 4필드)
매매 규칙은 **오직 이 4필드만** 보고 동작한다.

| 필드 | 값 | 의미 | 산출 |
|---|---|---|---|
| `type` | trend / range | 추세장 / 횡보장 | \|평균수익률\| ÷ 변동성 (크면 trend) |
| `direction` | long / short / none | 방향 (range면 none) | trend면 평균 로그수익률 부호 |
| `confidence` | 0~1 | **레짐 판단에 대한 확신** | filtered posterior γ_t = P(상태=k \| 관측) |
| `volatility` | 연속값 | 국소 변동성 | ATR(24봉), 가격 단위 |

### 2.2 매핑 규칙 (자동 번역, 사람이 라벨 안 붙임)
- 각 발견 상태의 통계를 규칙에 통과:
  - `|평균 로그수익률| / 변동성` 큼 → `type=trend`, 작음 → `type=range`
  - trend면 평균 수익률 부호 → `direction = long/short`; range면 `direction=none`
  - `confidence = filtered posterior γ_t` (반드시 filtering, smoothing 금지)
  - `volatility = ATR(24봉)`
- 동일 규칙이 K가 몇이든, 상태 번호가 뭐든 동일 작동.

### 2.3 핵심 분업 (confidence vs volatility)
- **confidence(확신) → Size** ("얼마나 믿고 베팅하나")
- **volatility(ATR) → SL/TP 거리** ("가격이 얼마나 출렁이나")
- 절대 섞지 않는다. 한 변수가 두 곳에서 작동하면 효과가 엉킴.

### 2.4 strength / volatility 설계 근거
- strength ≡ **filtered posterior γ** ("확신"의 문자 그대로의 정의). 지속성(self-transition)·기대수익 크기 후보는 "확신"이 아니라 제외.
- volatility 필드 = **진입 시점 ATR(국소 실현변동성)**, not 상태 분산.
  - 상태 분산 = 레짐의 시간평균적·구조적 변동성 → 이미 type 분류(수익률크기÷변동성)에 사용됨 → 중복.
  - ATR = 지금 이 순간의 국소 변동성 → SL/TP가 막아야 할 위험이 "지금부터의 노이즈"라서 국소값이 정합.

### 2.5 매핑 임계값 (미해결, 결정 필요)
- type 경계(수익률÷변동성이 얼마면 trend냐)는 누군가 정해야 함.
  - 옵션: 손으로 박기(약간의 통제) / 상태 통계 분포 기반 자동 클러스터링(완전 자유).
  - **[OPEN]** 1세대에서 어디까지 데이터에 맡길지 미확정.

### 2.6 2세대 후보 필드
- `transition_risk` (레짐 전환 임박도, self-transition 확률 기반). 선제 대응용. 1세대 제외.

## 3. 매매 레이어 — 추세매매 (type = trend)

### 3.1 진입
```
레짐이 trend로 전환 →
   confidence ≥ θ_trend (고정값, 백테스트 스윕) →
      그 봉 마감 직후 = 다음 봉 시초가에 시장가 진입 (direction대로 long/short)
   confidence < θ_trend → 이번 전환 건너뜀
```
- **confidence 게이트**가 진입 방식을 가르는 1차 스위치. 확신 충분하면 전환 즉시 진입, 애매하면 건너뜀("신중하게 풀백 확인"의 단순화 = "확신 없으면 안 함").
- 1세대는 **대기 조건 없음**(N봉 지속 확인·풀백 모두 제외). 가장 단순한 형태로 돌려 1h 노이즈성 전환 비용을 백테스트로 측정 후 2세대 대응.
- 진입가는 전환 확인된 봉의 **마감 직후 = 다음 봉 시초가**. 레짐은 직전 마감 봉으로
  계산해 미래참조를 차단하고, 실제 체결은 봉 마감 후 주문이 나가므로 다음 봉 시초가가
  정확하며 라이브-백테 일관(`close_T ≈ open_{T+1}`). (인프라 정합성 분석 결과 정정 —
  세션 원안의 "종가 진입"과 정보·인과 동일, 체결 시점만 더 정직.)

### 3.2 사이징
- **Size ∝ confidence** (확신 높을수록 크게). SL은 ATR 기준 유지 → 한 거래당 손실 비율 일정 → 리스크 관리 보존.
- ("확신 높으면 공격적으로"는 SL 확대가 아니라 Size 확대로 실현.)

### 3.3 청산 (보유 중 매 봉 병렬 확인)
```
1. 트레일링 SL (= 보유 중 SL 업데이트):
   LONG:  SL = max(기존_SL, 현재가 − k_trend_trail · ATR)   ← 유리한 방향만, 절대 안 내림
   SHORT: SL = min(기존_SL, 현재가 + k_trend_trail · ATR)
   닿으면 청산. **TP 없음 = 순수 트레일링** (추세 끝까지 타기).

2. 레짐 전환:
   - 적대적(반대방향 trend 전환) → 즉시 종료
   - trend → range 전환 → 트레일링 SL을 그 자리에 고정(더 안 올림),
                          range 동안 그 고정 SL만 방어선, 뒷 trend 대기
       · 같은 방향 trend 복귀 → 유지, 트레일링 재개
       · 반대 방향 trend 복귀 → 즉시 청산
```
- 초기 SL = `진입가 ∓ k_trend_sl · ATR`. 진입 시 설정.
- 트레일링 도입 이유: 추세매매 수익 엔진 = "가끔 오는 큰 추세를 끝까지 먹어 잦은 손실을 메움". 고정 TP는 이 엔진을 잘라버림. 레짐 전환 종료(하방 보호)와 트레일링(상방 확장)은 **반대 문제를 푸는 별개 장치**.
- range 구간 처리 우선순위: SL/트레일링이 1차 방어선(닿으면 청산), 통과한 포지션만 뒷 trend 방향 규칙(2차 판단)으로.

### 3.4 손익비
- 추세매매: **낮은 승률 + 큰 손익비** 구조. 순수 트레일링이라 고정 손익비는 없으나, 초기 SL 폭(k_trend_sl)과 트레일링 간격(k_trend_trail)이 리스크를 결정.

## 4. 매매 레이어 — 평균회귀 (type = range)

> 추세매매의 거울상. 위치 복귀에 베팅. **높은 승률 + 작은 손익비**. 트레일링 없음.

### 4.1 진입 — 셋업/트리거 2단계 상태기계
```
[셋업 대기]
   │  (LONG) 가격이 하단 볼린저 밴드 이탈  AND  RSI 과매도   ← 셋업(상태): 의미 있는 자리에서 충분히 눌림
   ▼
[트리거 대기 / armed]
   ├─ 가격이 하단 밴드 안으로 복귀 ─────────→ 【진입】(복귀 봉 마감 직후=다음 봉 시초가 LONG)   ← 트리거(사건): 위치 복귀
   ├─ 레짐이 range 이탈(confidence<θ_range or type=trend) → [평균회귀 중단]
   ├─ RSI 과매도 해제 (가격은 여전히 밴드 밖) ──→ [셋업 대기]로 리셋   (모멘텀만 식음 = 소강, 셋업 전제 붕괴)
   └─ 가격이 추가로 더 이탈 (거리 만료) ───────→ [셋업 대기]로 리셋   (셋업이 틀림 = 칼받기)
   SHORT은 상단 밴드 + RSI 과매수에서 대칭
```
- **진입 도구**: 볼린저 밴드 **AND** RSI (둘 다 충족). 볼린저=위치, RSI=모멘텀 상태. AND는 칼받기 후보를 자동으로 거름(매매 횟수는 줄지만 평균회귀는 승률 우선).
  - RSI 임계값은 백테스트 스윕으로 조절(과매도 30 vs 35~40로 횟수/질 균형).
- **반등 확인 방식**: 가격 기준(밴드 안쪽 복귀). RSI는 **트리거가 아니라 셋업의 상태 필터**로만 사용.
  - 근거: 평균회귀는 위치에 베팅 → 트리거도 위치(가격 밴드 재진입)로 보는 게 정합. RSI 반등은 가격 반등의 더 느린 후행 그림자(예측 아님). RSI 평활성은 상태 판단엔 강점, 타이밍 트리거엔 약점.
  - 1세대는 "밴드 안쪽 복귀"(파라미터 안 붙음). "충분히 가깝게 복귀"(거리 임계 파라미터)는 2세대.
- **만료 조건 3종(1세대)**: 레짐 range 이탈(중단) + RSI 과매도 해제(리셋) + 거리 추가 이탈(리셋). 시간 만료(N봉)는 2세대(RSI 해제가 낡은 셋업 청소를 상당 부분 대신함).
- **"복귀=진입" vs "이탈 지속=리셋"** 구분이 상태기계의 정수. 같은 "셋업 해제"라도 의미가 정반대.

### 4.2 사이징
- **Size ∝ confidence** (range 레짐 확신 기준). 추세매매와 같은 형태이나 **코드는 분리**(독립 진화 위해).

### 4.3 청산 (보유 중 매 봉 병렬 확인)
```
1. TP: 가격이 볼린저 중심선(이동평균) 도달 → 전량 익절   (중심 복귀 = 베팅 실현. 트레일링 없음.)
2. SL: 가격이 진입가 ∓ k_range_sl · ATR 도달 → 손절   (= "range가 아니라 돌파였다" = 레짐 오판)
3. 레짐 전환 (메인: range → trend):
   - 적대적(range-LONG인데 하방 trend / range-SHORT인데 상방 trend) → 즉시 종료
   - 우호적(같은 방향 trend) → **무시, 기존 TP/SL 그대로 유지** (전환 순간 익절 아님)
   - (range 유지되면 1·2가 처리)
```
- 손익비: TP가 중심선으로 고정 → 진입 위치에 따라 자연 결정. 1:1 근처 이하 가능, 높은 승률로 메움.
- 적대적 전환은 SL보다 먼저 발동 가능(SL 닿기 전 trend 확정 시 즉시 탈출).
- trend→range→trend 복귀 시나리오는 평균회귀엔 거의 무관(중심 닿으면 빨리 나와 포지션이 오래 안 남음).

## 5. 공통 원칙 (두 전략 위의 상위 규칙)

### 5.1 전략 완전 분리
- 추세매매·평균회귀는 **독립 모듈**. 사이징이 현재 같은 형태여도 코드 공유 금지(독립 진화 위해).

### 5.2 단일 포지션 원칙
- **한 번에 하나의 포지션만 보유.**
- 레짐 전환 시 순서:
  1. 이전 레짐 포지션을 **적대성 기준으로 먼저 처리**(적대적→즉시 종료, 우호적/중립→유지).
  2. 그 결과 **포지션이 비워졌을 때만** 새 레짐 전략의 신규 진입을 평가.
  3. 이전 포지션이 유지 중이면 **새 진입 보류**.
- (이 원칙이 같은방향 중복·반대방향 동시보유(헤지) 사고를 막음.)

### 5.3 표기 규칙 (구현 시 혼동 방지 — 전략별 접두어 필수)
| 추세매매 (trend) | 평균회귀 (range) | 비고 |
|---|---|---|
| `θ_trend` | `θ_range` | 진입 confidence 게이트 |
| `k_trend_sl` | `k_range_sl` | 초기 SL 계수 (의미 다름: 추세꺾임 거리 vs 돌파확정 거리) |
| `k_trend_trail` | — | 트레일링 간격 (평균회귀엔 없음) |
| TP 없음(순수 트레일링) | TP=중심선(계수 없음) | |

- **결코 같은 이름을 쓰지 않는다.** 의미·값이 모두 다르므로 접두어로 전략을 명시.
